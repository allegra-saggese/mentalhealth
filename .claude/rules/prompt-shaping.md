# Prompt Shaping (a standing habit, not a skill)

When a request arrives informal, dictated, or ambiguous, work out before acting what the concrete deliverable is, which files and prior decisions bear on it, and which constraints must hold — journal style, replication tolerances, reproducibility, no hardcoded paths, the data-and-secrets rules. Do this silently; the point is a better answer, not a visible form.

Make routine judgment calls yourself and state any consequential assumption in one line. Ask — briefly, via `AskUserQuestion` — only when different readings would lead to materially different work: which journal, which estimator, overwrite or append, which co-author's version wins. Those decisions belong to the user.

For multi-turn specification of a research idea (a fuzzy idea → a full spec), use [`/interview-me`](../skills/interview-me/SKILL.md); for tasks big enough to plan, shaping feeds the plan in [`plan-first-workflow.md`](plan-first-workflow.md).
